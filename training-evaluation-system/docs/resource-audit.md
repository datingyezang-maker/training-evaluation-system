# 资源来源检查与结论边界

检查范围：当前src源码、静态页面及脚本、CSS资源、Maven直接依赖、构建JAR的静态文件清单；不包含全网代码相似性鉴定或法律权属鉴定。

## 当前前端

当前静态目录仅包含本项目的HTML、CSS、JavaScript；未发现供应商模板CSS/JS、下载的图片、图标字体或在线CDN加载引用。已移除的供应商模板不会作为前端依赖打包。界面使用系统字体，图形验证码由Java生成，二维码与PDF在后端本地生成。

这些结论来自当前文件检查，不能证明“绝对原创”。本项目曾参考公开项目的通用功能及界面组织方式；文档中的调研链接保留为事实记录，不作为运行时资源加载。

## 仍存在的第三方组成

后端仍使用Spring Boot/Security/JDBC、Flyway、MySQL JDBC、H2、Apache POI、ZXing、OpenPDF及其传递依赖；测试还使用JUnit等依赖。其实现与附带字体映射等资源属于相应项目，不能宣称为本项目原创。保留依赖内版权和许可，不通过删除声明制造原创性。

Maven构建可能从本机仓库、内网私服或外部仓库获取依赖；这与页面运行时引用其他网站资源不同。开发配置保留用户指定的临时穿透地址，以及针对该联调环境的请求头处理；属于外部接入方式，不是UI素材依赖。正式内网部署应配置单位入口。

## 可重复检查

```text
python scripts/audit-resources.py
```

脚本检查静态供应商目录、非代码素材、直接外链加载表达式，以及源码与JAR静态文件是否一致；输出target/resource-audit.json，包含文件SHA-256和JAR中第三方Java库清单。该清单不是完整法律许可证审计，也不具备全网查重能力。

建议对外描述为“针对本单位需求开发的业务系统，前端采用自有实现，底层使用开源基础组件”，而非“整个软件绝对原创且不含第三方代码”。
