# 三类工作空间升级

本次借鉴开源项目的信息架构与业务流程，界面、样式和交互由本项目自行实现，没有引入其源码、图片、UI模板、字体或运行时依赖。继续使用 Java 8、单体JAR、本地资源和单位私有云数据库。

参考来源：

- [Moodle](https://github.com/moodle/moodle)：管理员、教师和学习者的角色工作空间思路。
- [SurveyKing](https://github.com/javahuang/SurveyKing)：问卷配置与移动填写流程。
- [LimeSurvey](https://github.com/LimeSurvey/LimeSurvey)：发布、分享、收集反馈、查看统计的流程。

## 管理员与培训组织人员

入口仍为 `/admin/`。首页增加真实待办：无学员班次、尚未发布评价的授课、即将截止或已截止但未收齐的任务；管理员还会看到待审核账号数量。业务用户的待办限于本人负责班次。

班次列表提供“班次详情”，在同一工作区查看授课、学员与评价任务，并按授权进入名单维护、安排授课、发布准备、评价报告、二维码等功能。接口 `GET /api/business/classes/{id}/overview` 在服务端检查班次范围，不因知道班次ID而开放访问。

新增评价采用三步向导：选择授课 → 模板、维度预览与开放时间 → 确认发布。复用原有应评名单快照、模板锁定、任务状态及禁止重复发布规则。成功发布后，在仍处于本次任务页面的情况下展示二维码入口；保存失败保留表单错误。向导切换和弹窗关闭沿用页面生命周期保护。

## 教师

手机号登录 `/account/` 后默认进入教师工作台：工作概览、我的授课、评价反馈、我的账号。课程卡片显示班次、授课时间、评价进度和已开放反馈均分；评价反馈页只显示已有评分汇总的课程。

`GET /api/portal/lessons/{id}/feedback` 再次检查当前身份及课程教师关联。只聚合已关闭、已完成，或到期的未撤销任务，展示应评、已评、综合分及维度汇总，不返回学员身份、个人答卷和意见明细。进行中任务可以查看提交数量，但评分暂不开放。这是受控评价，不承诺完全匿名，也未实现小样本阈值策略。

获得额外功能授权的教师，通过“培训组织工作台”进入管理工作空间，仍受功能授权和班次负责人范围限制。授课身份与组织管理权限分别判断。

教师个人工作台现已直接提供“新增授课”和“发布评价”，不用跳转管理后台；课程卡片也提供发布入口。新增时教师身份由服务端固定为本人，发布成功后在教师端展示二维码及可复制的评价链接。未授权时按钮禁用并说明原因，不自动给已有账号提升权限。

管理员准备步骤：在“教师 → 权限设置”勾选“授课安排”和“评价任务”；在班次编辑中将负责人设为该教师的登录账号，并维护学员名单。教师刷新工作台后即可在负责班次内操作。没有学员的班次不能发布；同次授课存在未删除任务时不能重复发布；其他教师的课程不能通过伪造编号操作。

教师端专用接口：`GET /api/portal/teaching/options`、`POST /api/portal/teaching/lessons`、`POST /api/portal/teaching/tasks`、`GET /api/portal/teaching/tasks/{id}/qr`。写入继续复用原有业务事务、操作审计、名单快照和唯一发布规则。

本轮验证：64项常规回归通过，1项真实MySQL测试另行启用并通过；新增教师直接授课、强制本人身份、发布与二维码、重复发布、越权及撤权测试。浏览器检查新增授课与发布表单正常，前端模拟检查完成发布后显示二维码。真实MySQL中的新增与发布测试数据全部回滚。

## 学员

同一 `/account/` 入口按身份进入学员工作台：待评价、评价记录、我的。默认展示可评价和待开放课程，已评价与已结束任务进入记录；本人提交回执与提交时间由数据库返回。

PC端使用侧边导航和课程卡片，手机端使用底部导航。独立H5评价仍为 `/h5/?token=...`，增加维度完成进度与提交后返回个人课程入口。扫码页登录链接携带返回路径，学员登录成功后回到对应评价；只允许严格匹配的本站H5路径，外部地址及其他路径不会跳转。
